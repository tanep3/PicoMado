# 初期値・変更範囲・検証待ち技術値

- 更新日：2026-10-12 UTC
- 状態：下記「確認済みの初期値」**７項目だけユーザー確認済み**。ポート以外は Web UI から変更・永続化できる要件。技術欄の仮値は承認に含まれない。
- 対象：[要件](requirements/README.md)、[共通カーネル](requirements/kernel.md)、[システム設計](system-design-draft.md)。この文書は実サービス、OS、ネットワーク設定を変更しない。

## 既に決まっていること

Web/API と Pico の通信は自宅 LAN・Tailnet 内だけで利用し、インターネットへ直接公開しない。PicoMado 独自の API キー・Web ログイン登録は設けない。家からは direct TCP、外出時は TailSocks の SOCKS5 経由。Web/API と端末通信は同じ番号のポートに置く。通信方式は HTTP/1.1 と WebSocket、Pi の設定・索引 DB は SQLite とする。

毎時の事前更新、天気の今日を含む７日、初期地点の東京駅、４ボタン GPIO と役割、初回の４プラグイン ON・順序・YouTube 表示、接続再試行の回数無制限は確定要件であり、ここで再決定しない。E-ink・２ボタン実機や BLK 結線後の確認は初版 LCD １台の受入と分ける。

## 確認済みの初期値

| 用途と所有者 | 初期値・単位 | 変更場所と反映時点 | 値を変えたときの影響 |
| --- | --- | --- | --- |
| 共通ポート・Pi 配備設定 | TCP **16153**。自宅 LAN と Tailnet の設定済みアドレスで同じ番号を使う。 | **Web UI では変更しない。** Pi の配備設定と Pico の家／外出先接続先を別途整合させる。実 IP は Git に固定しない。稼働前に既存機とのポート競合を確認する。 | 変更時は接続先と Web URL の更新が必要。既存機の資料にある 16151・16152 は変更しない。 |
| Wi-Fi 接続試行・端末別 | **15 秒** | Web UI の対象端末設定に保存。Pico への同期・不揮発保存後、**次の接続試行から**適用。 | 短いほど失敗判定が速いが、遅い接続を打ち切りやすい。 |
| Pi アプリセッション確立試行・端末別 | **10 秒** | 同上。現接続は切らず、**次の試行から**適用。 | 短いほど復帰判断が速いが、遅い経路では失敗が増える。 |
| 再試行間隔・端末別 | 最初 **5 秒**、段階的に延ばして最大 **30 秒**。試行回数は既決の無制限。 | 同上。進行中の試行・待ち時間を中断せず、**次の再試行周期から**適用。 | 短いほど復帰が速いが試行が増える。延長方法の細部は実装・実測で調整する。 |
| 生存確認・端末別 | Pico の heartbeat **15 秒間隔**、Pi は最後の有効通信から **45 秒**でオフライン判定。 | Web UI の対象端末設定に保存。Pico が新改訂を不揮発保存して応答し、その改訂の heartbeat を Pi が確認してから新値へ切替。 | 短いほど断線検出が速いが通信量・一時遅延による誤判定が増える。 |
| 公開気象データ取得・プラグイン別 | 天気・雨雲の外部 HTTP 取得は１回 **20 秒**でタイムアウトし、初回後に **２回**再試行。 | Web UI の天気・雨雲それぞれのプラグイン共通設定に保存。**次に開始する取得ジョブから**適用。 | 増やすと成功機会が増す一方、最終エラー画面までの時間と負荷が増える。風刺画生成や YouTube 変換には流用しない。再試行間隔は未確定。 |
| ２ボタン長押し・端末別 | **1.8 秒** | Web UI の対象端末設定に保存。Pico への同期・不揮発保存後、**押下中でない次の入力から**適用。 | 短いほど反応は速いが短押しとの誤判定が増えやすい。４ボタンの電源押下時間は既存操作を照合して別途決める。 |
| YouTube 初期 FPS・プラグイン共通 | **6 fps**。Web で選べる値は **6・12・18・24・30 fps**。 | YouTube プラグイン設定に保存。**次に準備する動画／変換ジョブから**既定値として適用。動画ごとの明示指定は優先する。 | 高いほど滑らかになる可能性があるが取得・変換・通信・描画負荷が増える。30 fps の実機達成は未検証。 |

「７項目」はポート、Wi-Fi／Pi アプリ接続試行、再試行、生存確認、気象取得、長押し、YouTube FPS の会話上の数え方。表では Wi-Fi と Pi アプリの試行を別行で示す。

## Web 変更と Pico への同期契約

- 端末別値の正本は Pi の対象端末設定。Web 書込みは期待設定改訂を添え、範囲と値の関係を検査してから原子的に保存する。オフライン端末にも保存し、次のアプリセッション成立後に同期する。未同期・適用済みの改訂を Web に区別して示す。
- Pico は受け取った設定改訂を検証して不揮発に保存し、同じ改訂の再送には冪等に応答する。ネット接続前には前回正常に保存できた値を使い、初回起動や保存値破損時には上表の組込み初期値へ戻す。秘密値と接続先の設定はこの Web 変更機能から勝手に書き換えない。
- 設定送信や応答の遅延で現在の接続を切断しない。接続・再試行値は次の試行から、長押しは次の押下から使う。生存確認の移行中は Pi 側の判定期限を旧値・新値の長い方で保ち、Pico が新改訂の heartbeat を送ったときに新値へ切り替える。同期が失敗したら保存済み希望値を維持し、再接続時に再送する。
- 気象取得と FPS はプラグイン所有。端末接続設定とは別の設定改訂を使い、進行中の取得・変換ジョブは旧設定の結果として扱う。新値は次のジョブから適用し、対象・条件が異なる完成物を同じキャッシュとして混ぜない。

### 入力検証の設計範囲

| 値 | Web/API で受理する範囲と関係 |
| --- | --- |
| Wi-Fi 試行 | 5～120 秒の整数。 |
| Pi アプリセッション試行 | 3～120 秒の整数。 |
| 再試行開始・上限 | 開始 1～60 秒、上限 1～300 秒の整数で、開始 ≤ 上限。試行回数は無制限のまま。 |
| heartbeat・オフライン判定 | 間隔 5～120 秒、判定 10～600 秒の整数で、判定 ≥ heartbeat の２倍。 |
| 天気・雨雲 HTTP 取得 | １回の timeout 5～120 秒、追加再試行 0～5 回の整数。各プラグインで独立。 |
| ２ボタン長押し | 1,500～2,000 ミリ秒の整数。２ボタン能力のない端末には適用しない。 |
| YouTube 既定 FPS | 6・12・18・24・30 fps のいずれか。 |

範囲外、関係違反、能力非対応、古い設定改訂の書込みを拒否し、既存の有効な値を変えない。範囲は実装の入力契約として試験し、実機測定で必要なら設計改訂する。

## 未承認の内部検証開始値・上限案

以下は**ユーザー確認済みの７項目に含まれない仮値**で、受入合否の閾値ではない。Pico のメモリ、LCD 描画、長時間接続、複数端末負荷で調整する。

| 技術項目 | 仮値・単位 | 用途と根拠 | 設定場所・変更影響 |
| --- | --- | --- | --- |
| 端末別送信待ち | 合計 **256 KiB／端末**、最大論理画像 64 KiB と制御 16 KiB のため **80 KiB** を確保。古い未送信動画を間引き、動画は送信中 **１フレーム／端末**。 | 遅い端末による無制限蓄積を防ぐ。LCD RGB565 の全画面は 160×80×2 = 25,600 バイト。 | Pi 送信キュー Config。端末数に比例するメモリと再描画回数を実測する。 |
| 並列 worker | 取得 **２ジョブ**、変換 **１ジョブ**を上限。プラグイン／端末の待ち行列を順番に処理。 | 初回は CPU・ディスクを占有させず、他端末を待たせない。 | Pi EffectRunner Config。スループットと負荷を実測する。 |
| 通信メッセージ長 | 制御本体 **4 KiB 以下**、画像の１チャンク **4 KiB 以下**、１論理画像 **64 KiB 以下**。 | Pico W で大きな単一受信バッファを要しない。 | プロトコル版と Pi/Pico 共通 Config。実装前のメモリ試験で最終化する。 |
| 描画確認期限 | `ReceiptAck` **5 秒**、LCD の `RenderedAck` **10 秒**。E-ink は実機で別の期限を決める。 | 受信と物理描画を別々に観測する。 | Pi セッション Config。短すぎると正常描画を失敗扱いする。 |
| SQLite 書込み待ち | `busy_timeout` **3 秒**、WAL 使用。画像・動画ファイルは DB 外。 | 短い設定更新が競合した際に待ち、長い IO を書込み中へ入れない。 | Pi 永続化 Config。ディスク遅延の実測で調整する。 |
| 気象取得の再試行間隔 | 追加２回の間隔に **5 秒、15 秒**を仮置き。 | 短い障害の吸収。 | 天気・雨雲のプラグイン Config。取得負荷と最終エラーまでの時間を測る。 |
| チャタリング除去 | **30 ミリ秒**を仮置き。 | 押下時 LOW の接点雑音を抑える。 | Pico ハードプリセット。実機で誤入力と応答を測る。 |

## 実測や既存機の照合後に決める値

キャッシュ容量の運用閾値と風刺画の生成／取得ジョブ時間は、元ソースの追加照合と新環境での測定後に提案する。E-ink の描画期限・更新頻度、BLK の極性、気象庁データの地域別成立、応答・fps・復帰・長期安定の受入閾値も実機または測定計画で確定する。２ボタンの GPIO・共通 GND・電気条件は[共通カーネル要件](requirements/kernel.md)で確定済み。上の技術仮値を確定扱いしない。
