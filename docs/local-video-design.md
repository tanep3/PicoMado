# ローカル動画プラグイン設計（LOCAL-VIDEO-20261105）

[要件](local-video-requirements.md)に基づく。実装前に固定した境界を記す。

## 既存経路との比較

YouTube プラグインは `yt-dlp` で原本を取得した後、ffmpeg で有限 JPEG 列を作り、`PlaybackSpec` と `run_playback` で各端末に RGB565 を配信する。新プラグインは取得段だけをローカルファイルへ置き換え、`PlaybackSpec`、共通再生ループ、配信・世代・端末制御を共有する。動画ごとの状態、変換、キャッシュはプラグインが所有し、application / transport に ID 分岐を増やさない。

## 状態と遷移

| 状態 | 入力 | 結果 |
| --- | --- | --- |
| 空・再生中 | prepare(file,fps) | 現在再生を保持し、`prepare` ジョブを登録 |
| prepare 中 | prepare | busy として拒否 |
| prepare 中 | 成功（同じ generation） | 完成キャッシュを追加し共有時計を新規開始 |
| prepare 中 | 失敗・取消し | ジョブ結果だけを更新し以前の再生を保持 |
| 準備済み | play(asset) | キャッシュ検証ジョブ成功後に共有時計を開始 |
| 再生中 | stop | 共有再生を解除し選択端末を更新 |
| 準備済み | delete(asset) | 対象のみ削除。対象の再生は停止 |
| 原本あり | delete_import(name) | 原本のみ削除。完成キャッシュとその再生は維持 |
| 起動時 | 保存状態読込み | アクティブな変換キャッシュを検証後に再生復元 |

ジョブ結果は共通 JobToken とプラグイン内部 generation の両方で照合する。古い結果は現在の再生へ反映しない。完了とは ffmpeg 終了だけではなく、連番・JPEG サイズ・160×80 デコード検証済みのキャッシュ公開を指す。

## IO と識別

専用アップロード API は通常のファイル選択で受けたバイト列を 512 MiB まで逐次書き込み、`data/imports/` の隠し一時ファイルで検査後、同名がないときだけ公開する。切断・上限超過は一時ファイルを掃除する。サーバ上のパス指定は受けない。

`data/imports/` の通常ファイルを読み、`cache/videos/<content-key>/frame%08d.jpg` に変換を公開する。key は原本内容ハッシュ、FPS、既存 YouTube 変換版から生成する。ffprobe、ffmpeg、160×80 JPEG 検証、子プロセス取消しは既存 YouTube の有限動画変換処理をローカル入力へ適用する。ジョブは app lock 外で実行する。作業ディレクトリから完成領域への rename を公開点とし、途中成果を再生に使わない。読み出しは既存の JPEG → RGB565 関数を用いる。準備・読み出しはファイル名/キーを検証し、symlink を辿らない。

## 検証境界

単体試験で入力・遷移・保存復元、統合試験で短い合成 MP4 の変換とフレーム読み出しを確認する。参考素材の Library 取得に成功すれば同じ 2 fps 素材も使う。root gate と cargo tests を実行する。実機・本番サービス・push は行わない。
