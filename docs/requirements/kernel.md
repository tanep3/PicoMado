# 共通カーネル要件

[要件定義書の案内](README.md)に戻る。初版の実機受入は LCD・４ボタン１台。サーバは Rust、Pico ファームウェアは C/C++ を想定する。契約・構造・状態遷移の設計思想は全体要件の方針に従い、具体的な API などは設計時に定める。共通カーネルは取得データの内容やプラグイン固有の表示状態を決めない。

LCD ４ボタン端末と電子ペーパー（E-ink）２ボタン端末で対応可能なプラグインを共用できるようにする。端末ごとのディスプレイ種別やボタン数などを Web UI で設定できる構造も要件とする。具体的な方式や対応範囲は設計事項（U-02～U-04）。E-ink 端末の静止画・更新頻度の制約を LCD へ一律に適用しない。共有可能な基盤の設計と、既存 E-ink 製品への実装移行は別の判断とし、後者は今回承認されていない。

一つの Pi サービスで複数端末に対応できる構造とし、端末 ID ごとの独立した論理セッションを扱う。論理セッションは操作・表示・接続状態を管理する単位であり、常時 TCP 接続を義務づけない。一台の待機や切断が他端末の操作・画面・再生を変えない。共通サービスの具体的な配置・通信 API の詳細・復帰手順は未決（U-02、U-03）。

同じ device_id の端末が再接続したら、新しい接続を有効とし、旧接続を終了する。旧接続から遅れて届く操作・応答・切断 callback で新しいセッションの状態やオンライン表示を変更しない。接続世代番号などの識別方法は設計事項（U-02）。これは同一端末の再接続を扱う規則であり、別々の Pico に同じ device_id を誤設定した衝突とは区別する。PicoMado 独自の API キーや Web ログイン登録は設けない。

Pico からの通信が届いた時点で device_id を基に端末を自動登録する。初版の LCD・４ボタン端末は初回に４プラグインをすべて利用 ON とし、共通初期順序は YouTube→風刺画→天気→雨雲レーダー、初回表示は YouTube とする。Web UI で端末 ID ごとに利用可能なプラグインを ON/OFF チェックし、その設定を Pi サービスが永続保存する。共通順序を変更した後も各端末では利用 OFF の項目を除いて使い、前回表示したプラグインが無効なら利用可能な先頭を表示する。能力非対応のプラグインは Web UI に理由を表示して利用 ON にできず、初回登録時も ON にしない。すべて無効なら画面中央に「PICO窓」を表示し、少なくとも Web UI から設定できる状態を保つ。通常接続中は本体設定メニューを設けず、プラグイン選択順序の末尾にも追加しない。起動・再接続・接続失敗中の設定入口は本書の起動・接続規則のとおり維持する。

Web UI の共通設定にプラグイン一覧を置き、↑↓ボタンで並べ替えて保存する。保存した全端末共通の順序を使い、端末ごとに利用 OFF の項目は選択列から除く。初期順序は上記の４機能順とし、画面の細かな配置だけを設計事項とする（U-04）。

Web UI のホームに各プラグインページへの入口を置き、各プラグインページにホームへ戻るボタンを置く。メインシステムとプラグインは同じポートで提供し、API エンドポイントで機能を制御する。初期ポートは TCP 16153 とし、Web UI では変更しない。稼働環境のアドレスと接続先の整合は U-08 で確認する。

Web/API と Pico の端末通信は自宅 LAN と Tailnet 内に限定し、インターネットへ直接公開しない。PicoMado 独自の API キー・Web ログイン登録は不要。Pi サービスは設定した自宅 LAN・Tailnet の宛先アドレスで受け、全インターフェースへの無条件バインドはしない。実際のアドレスは稼働環境に合わせて設定し、初期ポート 16153 は Pi の配備設定と端末接続先で一致させる。公開範囲の決定は OS・ルータ・Tailscale の現行設定変更を許可するものではない。入力・メッセージ長の検証と秘密値の非記録は従来どおり行う。

## プラグイン Web 画面と責務境界

2026-10-18追加の時計もこの共通契約に従う。初版４種の記述に対する追加範囲と、保存済み順序・選択・端末別有効化を変更しない移行は [時計要件](plugins/clock.md) を参照する。2026-10-20現在の実装適合、逸脱、共通メニューの未実装は [対応確認](../history/implementation-conformance-20261020.md) に記し、実装上の不足を要件の撤回として扱わない。

2026-10-20 の責務確認：サーバがプラグインのドメイン状態・規則・内容を所有し、Pico は受信した端末 API を検証・振分け・実行して結果を返す。Pico にプラグイン ID やサーバの業務手順を持たせない。端末の接続・表示世代・物理入力・非同期ハード処理に必要なローカル状態は維持する。観測は共通の受信・判断・遷移・出力・完了／拒否の境界に置き、満杯や切断で通常処理を待たせず、欠測を区別する。具体的な段階移行・互換性・受入条件は [契約と観測の設計](../contracts-observation-design.md) に記す。

各プラグインの Web 画面では、共通コンテンツエリアとデバイスごとの設定項目を分けて構成する。共通コンテンツエリアの操作がどの端末へ影響するかはプラグインが決め、全プラグインで全端末への反映を強制しない。端末ごとのプラグイン利用可否の ON/OFF は共通基盤が管理する設定であり、プラグイン固有の端末別設定項目とは区別する。

共通基盤がページの共通枠と対象端末の選択 UI を提供し、プラグインが共通コンテンツエリアと端末別設定エリアの項目・処理を提供する。操作が共有対象へ作用するか対象端末へ作用するかを画面上で示す。端末別項目のないプラグインには無理に項目を作らない。共通エリアの内容や操作の影響範囲はプラグインが決め、基盤は全端末への一律反映を強制しない。画面の具体的な配置と項目の受け渡し方法は設計事項（U-03、U-04）。

プラグインは Web 画面に加え、共通の登録・入力配送・描画送信手段を利用する拡張単位とする。具体的な登録形式とインターフェースは未決（U-03、U-04）。

共通基盤は device_id、接続、端末ごとの選択プラグインと表示能力を管理し、入力イベントを該当プラグインに配送する。プラグインが指定した端末へ描画を送る手段も提供する。表示内容、端末間の共有範囲、再生状態と送信先の選定は各プラグインの責務とする。基盤が「同じプラグインを選んだ全端末へ同じ内容を送る」規則を強制しない（具体的なインターフェースは U-03）。

端末ごとの選択プラグインは Pi の共通基盤で管理する。現在表示すべき内容とプラグイン内の操作状態は、基本的にサーバ側の該当プラグインが保持し、Pico は受け取った内容を表示する。共通基盤は通信、待機、入力モード、接続中画面を引き続き扱う。保存済み設定・取得データと、一時的なサブモード・閲覧位置は区別する。再起動後は前回選択プラグインの通常画面から始め、一時的なサブモードと閲覧位置は復元しない。天気は今日、雨雲は取得セット内の最新観測を通常表示する。保存方式の詳細は設計事項（U-06）。Pico は下／次、上／前などのボタン操作を通知し、基盤が共通の切替処理で選択状態を更新する。プラグインは入力イベントを受け、内容と送信先を決め、基盤の送信手段で端末へ描画を届ける。サーバから自身への HTTP 呼出しは必須ではない。サーバ側で表示対象を更新したことと、端末画面に実際の表示が完了したことは同一視しない。完了通知・確認方法は U-03。

サブ機能ボタンには、項目一覧を表示するメニュー型と、動的なアクションを行う操作モードへ入る型の２通りを共通基盤として用意する。基盤は共通の入力・表示・モード管理を提供し、型の選択、具体的な動作と状態はプラグインが担う。天気と雨雲レーダーは時系列の操作モード型、YouTube と風刺画は当面サブ機能なしで押下しても無反応とする（本書の「起動・接続とボタン操作」）。

初期の Pico ファームに、共通のメニュー表示・操作を行う基盤を実装する。この基盤が扱える範囲では、サーバから渡すメニュー項目を後から追加できる構成を目指す。メニューのデータ形式・画面遷移・対応範囲は設計事項（U-03、U-05）。基盤の対応能力を超える表示・入力や新しいハード機能まで、サーバ側だけで追加できるとはしない。項目一覧メニュー型と、天気・雨雲の時系列を含む動的操作モード型の両方を扱う。

`systemd` は Pi サービスの起動・監視を担い、接続中の端末を判定する主体ではない。Pi サービスが端末 ID とセッションを基に接続状態を管理する。Pico の heartbeat 初期値は 15 秒間隔、Pi のオフライン判定は最後の有効通信から 45 秒。端末別 Web 設定で変更・保存できる。判定方式の詳細は設計事項。

オフライン端末も Web UI に状態表示し、設定できる。端末別の接続試行・再試行・heartbeat・オフライン判定・２ボタン長押しは Pi に希望設定として改訂付きで保存し、再接続時に Pico と同期する。Pico は検証後に不揮発保存して改訂を応答し、ネット接続前には前回正常値、初回・破損時には組込み初期値を使う。改訂・範囲・相互関係・能力を検証し、同期失敗時は希望値を保持する。接続中の端末を設定変更だけで切断せず、接続値は次回試行から、長押しは次の押下から適用する。heartbeat の移行は新改訂の heartbeat を確認するまで旧新の長い判定期限を使う。Web に未同期と適用済みを区別して示す。オフライン中の変更は保存し、再接続時に適用する。不要端末は Web UI から削除でき、Pi サービス側の端末利用設定を除去する。オンライン端末を削除したときは現在のセッションも終了する。Web UI には再接続すると新規端末として一覧に再登場する旨を示す。削除済みの device_id が再び通信してきたら、旧端末固有設定を復活させず、対応可能な初期プラグインを ON にした新規端末として自動登録する（初版 LCD 端末では４機能 ON）。順序はその時点で保存されている全端末共通順序を適用し、未変更なら初期順序の先頭である YouTube を表示する。Web で手動登録する操作は設けない。端末側の Wi-Fi 資格情報やファームを消す工場初期化は行わない。

情報取得・更新、表示内容、プラグイン内の操作状態と共有範囲は各プラグインが担当する。端末ごとの選択プラグイン、省電力、接続状態は基盤が扱い、非選択機能や別端末からの意図しない画面上書き・停止・操作の混入を防ぐ。表示能力差と物理ボタンの論理入力への変換方法は設計時に選ぶ（U-03、U-04）。

画面サイズ・色深度・更新頻度などの端末能力を管理し、プラグインの対応可否を判定する。必要能力の宣言形式は設計時に定める（U-03）。 端末能力上対応できないプラグインは Web UI に非対応の理由を示し、利用 ON にできない。E-ink 端末でも YouTube は制限付きの対応機能として選択できるようにする。滑らかさや LCD と同等の品質は保証せず、飛び飛びの表示を許容する。端末能力に応じたフレーム間引きなどの転送・描画方法は設計事項（U-03、U-14）。ほかのプラグインを全端末で同じ形で表示できるとは限らない。既存 E-ink 製品の改修・移行は今回承認されていない。

基盤は、将来プラグインが端末別の再生状態を持ち、対応済みの描画・入力能力の範囲で異なる動画を表示できる構造とする。他プラグインにも共有を強制しない。新しいコーデックやハード機能までファーム変更なしで対応できるとは約束しない（U-03、U-14）。

## 設計・試験で具体化する事項

接続世代と表示内容の切替世代を別に識別し、遅延フレームや ACK が現在の表示を上書きしない契約を検討する。ACK には対象の表示／フレームを識別できる情報が必要になる。接続世代番号や表示世代番号そのものの採用は未決で、同一端末再接続時に新接続を優先する既決規則を満たす方式を選ぶ（U-02、U-03）。

TCP 上のメッセージは長さと種別を判別できるフレーミング、分割受信、異常な長さ・破損・タイムアウト時の処置を設計する。受信したことと LCD／E-ink への描画が完了したことは区別し、それぞれの ACK／通知が何を保証するかを定める。端末ごとに有界の送信待ちを設け、送信前に古くなった動画フレームを破棄する案を評価する。遅い端末が別端末の送信を止めず、共有中の動画位置は YouTube プラグインが管理する既決の責務分担を守る（U-02、U-03、U-14、U-15）。

2026-10-21 の共通画像送信方針：既存 push 能力を持つ LCD と E-ink は、送信中１枚＋未送信最新１枚に制限し、各画像の描画 ACK を次画像の送信許可としない。Pico の既存 ACK は表示状態の報告として受け、物理描画の証明と TCP 送信受付を区別する。端末ごとの画素形式・E-ink 更新方式と、旧 LCD の ACK 許可契約は維持する。欠落した入力パケットそのものはこの方針で修復しない。[設計差分](../changes/LCD-ACKLESS-20261021.md)。

設定の正本を、端末側 Wi-Fi・ハード／端末 ID、基盤が扱う共通順序・端末別利用可否・選択プラグイン、プラグインが扱う地域・コンテンツ、一時的な入力モードに分けて明文化する。一時モードの端末・サーバ間の同期と、保存すべき設定の原子的な更新を設計する。接続設定の移行時には旧接続試行を無効化し、遅れて届く完了通知で新しい選択を戻さない。ビルド時には同じ device_id の重複を検出する案を検討する。別端末の ID 誤設定・なりすましへの耐性は同一端末再接続とは別課題であり、PicoMado 独自の API キー・Web ログイン登録は設けない（U-02、U-05、U-06、U-17、U-18）。

端末別の状態・最終通信時刻・エラー種別をログと Web UI でどのように示すかを設計し、全国地図が小画面で判読できるか実験する。各要件と対応する試験の期待結果・合否を紐付ける。応答時間、接続復帰時間、動画 fps・遅延、長期安定、消費電力、他プラグインへの阻害を測定項目とするが、合格閾値や測定期間はまだ定めない（U-03、U-04、U-10、U-14、U-15）。

## 共通ソース、設定とビルド

共通ソースは端末ごとにコピーせず共有する。共通設定、ハード構成プリセット、端末別上書きを分け、端末 ID 単位でビルド出力フォルダと UF2 を分離する。端末別 Config にボタン定義を持ち、日常の機能選択や利用可能プラグインなどは端末が対応できる範囲で Web UI から設定する。ハード対応はファームウェアが提供する範囲に限られ、Web 設定だけでドライバや物理配線は変更できない。設定形式・CLI・ディレクトリ構成とビルド手順は未決（U-04、U-17）。端末 ID は IP と分離し、IP 固定値のファーム焼込みを必須としない。DHCP 予約は選択肢の一つ（U-08、U-17）。

## Wi-Fi プロファイルと接続経路

SSID とパスワードのペアを複数登録し、端末設定のネットワーク項目で家／外出先テザリングを選べるようにする。秘密値は Git 管理外に置き、`config.sample` などに実値を書かない。自宅は Pi5 の自宅 LAN アドレスへの direct TCP、外出先は Pico からスマートフォンの TailSocks SOCKS5 に接続して Pi5 へ進むプロファイル方針が了承された。当初実験はTailnet IPv4宛で、2026-10-13の本環境では既存 subnet routing を使う LAN 宛先 `192.168.0.120:16153` でも成功した。両プロファイルは同じPiサービスでも経路が異なり、宛先IPが同じ場合もある。Tailnet参加だけでLAN到達を保証せず、別環境ではTailSocks側の経路利用とアクセス許可・対象待受を確認する。Wi-Fi の選択・再試行とメニュー操作は本書の「起動・接続とボタン操作」、設定の保存方式や失敗後の扱いは U-18。

**実測済みの範囲。** [接続技術ガイド](../guides/home-away-connectivity-technical-guide.md) と [2026-10-11 の実験記録](../../experiments/tether-tailnet/results-2026-10-11-tailsocks.md) によると、非 root の Android 16 上の TailSocks v4.9.1 で、Pico → スマートフォンのテザリング側 `10.101.65.232:48115`（SOCKS5 認証）→ Pi5 Tailnet `100.64.0.9` の接続が成功した。Pi5 は TailSocks ノード `100.64.0.18` からの着信として観測した。同じ Pico 起点の持続 TCP 上で Pi5 の PUSH と Pico の ACK も成功した。これらの値は試験時のアドレス・ポートであり、特にテザリング側 IP は固定保証がない。SOCKS5 が指定された TCP を中継した結果で、スマートフォンのホットスポット全体を透過的に VPN 化したものではない。

**製品取り込み時の実測。** LCD１台で自宅direct TCPのHello・画像ACKを確認した。2026-10-13はAWAYのTailSocks METHOD/AUTH/CONNECTとACTIVE/READY、LAN宛先のWebSocket Hello・受信ACK・描画ACKを照合し、既存LAN待受だけで成功した。[今回の検証記録](../../experiments/tether-tailnet/results-2026-10-13-picomado-away-lan.md)。既存subnet routingに依存する結果で、追加listenerやネットワーク設定変更は不要だった。

**未検証。** HOME全操作の再接続問題が解消したとは断定しない。既存YouTubeアプリへの取り込み、長時間接続、動画帯域・遅延、切断・切替後の復帰、複数実機の受入は未完了。プロファイル内でサーバ宛先と SOCKS5 接続先をどう保存・更新するかも設計事項（U-15、U-18）。既存の YouTube 本番サービス、Tailscale、ルータ設定はこの文書改訂で変更しない。

## 起動・接続とボタン操作

物理的な電源投入時には、前回選択したネットワークへの接続を試みる。接続成功は Wi-Fi 接続だけではなく、Pi アプリケーションのセッション確立までを指す。成功後は前回選択したプラグインの通常画面を表示する（無効時は上記のプラグイン選択規則を適用）。再起動前に時系列などのサブモードを開いていても、その閲覧位置は戻さず、天気は今日、雨雲は取得セット内の最新観測を表示する。失敗した場合は選択中のネットワークで再試行し、回数に上限を設けず電源 OFF まで繰り返す。プラグイン稼働後に Wi-Fi が失われた場合も画面を「Wifi接続中」に切り替え、起動時と同じ選択中ネットワークの再接続を繰り返す。Wi-Fi がつながっていても Pi サービスに到達できない場合やアプリケーションのセッションが切れた場合は「サーバ接続中」と表示し、同じネットワーク／接続経路でセッション確立まで再接続を繰り返す。試行タイムアウトと再試行間隔は Config で設定可能にする。初期値は Wi-Fi 接続試行 15 秒、Pi アプリセッション試行 10 秒、再試行間隔 5 秒から最大 30 秒で、端末別 Web 設定から変更・保存できる。試行は回数無制限とする。別プロファイルへの自動切替は未合意。ここでいうボタンによる「電源 OFF」は物理的な給電遮断ではなく、省電力待機を指す。待機中は Wi-Fi を停止してよい。コンセントを抜く物理断は別の状態である。

単なる一時的な通信断でも選択中の同一プロファイルで再接続し、Pi アプリケーションのセッション成立後は前回選択プラグインの通常画面に戻る。通信断前の一時的なサブモードや閲覧位置は復元しない（無効なプラグインの場合は上記のプラグイン選択規則を適用）。セッション復帰の具体的な手順は設計事項（U-02）。

### 主な状態と遷移

| 現在の状態 | 契機 | 次の状態・表示 | 確認条件 |
| --- | --- | --- | --- |
| 物理起動・待機 | 起動・復帰 | 前回選択ネットワークの接続試行。「Wifi接続中」 | 前回ネットワークを使い、一時的なサブモードは復元しない。 |
| Wi-Fi 接続中 | Wi-Fi 成立 | Pi アプリセッション確立を試行。「サーバ接続中」 | Wi-Fi 成立だけで通常画面に進まない。 |
| サーバ接続中 | アプリセッション成立 | 前回選択プラグインの通常画面 | 無効なら上記のプラグイン選択規則を適用する。 |
| 通常画面 | Wi-Fi 喪失／アプリセッション断 | それぞれ「Wifi接続中」／「サーバ接続中」 | 同じプロファイルで再試行し、復帰後は通常画面へ戻る。 |
| 接続試行中 | サブ機能入力 | 試行をキャンセルして本体設定メニュー | メニュー中は再試行を止め、確定／キャンセルは次段落の規則に従う。 |
| 通常画面 | サブ機能入力（対応プラグイン） | 時系列操作モード | 閲覧中の取得セットを維持し、キャンセルで最新セットの既定画面へ戻る。 |
| 通常画面 | 電源／待機入力 | 省電力待機 | LCD は黒表示、E-ink は直前画像を保持し、更新しない。 |
| 時系列操作モード | 電源／キャンセル入力 | 通常画面の既定表示 | 閲覧中の取得セットを解放し、最新セットへ切り替える。待機しない。 |
| 項目一覧メニュー | 電源／キャンセル入力 | メニューを取消す | 接続設定では変更を破棄し、元のプロファイルで再試行する。待機しない。 |

状態の実装表現、試行タイムアウト、接続世代と表示世代の扱いは U-02・U-03・U-18 で設計する。

起動時、プラグイン稼働後の Wi-Fi 喪失時、Wi-Fi 接続中の Pi サービス不達時のいずれも、接続失敗中や接続作業中にはサブ機能入力（４ボタンでは左上、２ボタンでは上長押し）から本体設定メニューを開ける。この入力は接続処理中にはプラグインへ渡さない。接続作業中に押した場合は進行中の接続をいったんキャンセルする。接続設定メニュー中は再試行を停止する。ネットワーク設定項目で家／外出先テザリングを選択でき、決定すると選択を保存して接続する。キャンセルすると変更を破棄し、元のネットワークで接続を再開する。設定メニューのその他の項目や画面遷移は未決（U-05）。

待機中の E-ink は直前の画像を保持し、画面をクリアしない。通知などを受けても待機中に画面を更新しない。LCD は黒画面を表示し、BLK を OFF にする。現状の PicoMado は BLK が未結線のため、ソフトウェア上の黒画面は表示できてもバックライトの物理的な消灯はできない。結線後に BLK の実機極性を確認して OFF 制御を完成させる（U-07）。待機からの復帰時は、物理起動時と同様に前回選択したネットワークへ接続し、接続中画面を表示し、Pi アプリケーションのセッション成立後に前回選択したプラグインの通常画面を表示する（無効時は上記のプラグイン選択規則を適用）。待機前の一時的なサブモードや閲覧位置は復元しない。

選択したネットワークはコンセントを抜いた後も記憶する。技術的に難しい場合に限り、起動時の家プロファイルを既定にしてよい。単純で変更頻度の低い設定を不揮発に保存することは可能だが、保存媒体・書込みタイミング、初回起動やデータ破損時の初期値は設計事項（U-18）。

ボタンの論理役割は端末別 Config で定義する。PicoMado の４ボタンは次の配置とする。GPIO と物理ピン番号は区別する。

| 位置 | GPIO／物理ピン | 通常時の役割 |
| --- | --- | --- |
| 左上 | GP12／16 | サブメニュー |
| 左下 | GP14／19 | 電源兼キャンセル |
| 右上 | GP13／17 | 上選択／前のプラグイン |
| 右下 | GP15／20 | 下選択／次のプラグイン |

E-ink ２ボタン端末の GPIO と物理ピン番号は次のとおり確定する。既存 E-ink 製品の改修は別途判断する。

| 位置 | GPIO／Pico W の物理ピン | 短押し | 長押し |
| --- | --- | --- | --- |
| 上 | GP20／26 | 上選択／前のプラグイン | サブ機能呼出し／項目一覧メニュー内の決定 |
| 下 | GP21／27 | 下選択／次のプラグイン | 電源・操作モード／メニュー内のキャンセル。待機からの復帰も長押し |

両ボタンの共通 GND は Pico W の物理28番とする。各ボタンは GPIO と共通 GND の間に接続し、GPIO の内蔵プルアップを有効にする。押下時 LOW（active-low）として扱う。

通常時の上下ボタンは、各端末で利用 ON のプラグインを全端末共通の順序で前／次に切り替える。YouTube と風刺画は当面サブ機能なしとし、サブ機能ボタンを押しても無反応でよい。天気と雨雲レーダーはサブ機能ボタンで時系列操作モードに入り、上下で時点を変える。電源ボタンをキャンセルとして押すと、デフォルト表示へ戻ってモードを終了する。時系列操作モードは項目一覧から決定するメニューとは区別する。基盤が両型の共通入力・表示・モードを扱い、型の選択と表示時点・内容・取得更新はプラグインが決める。通常接続中に本体設定メニューへの入口は設けない。２ボタン端末では短押し上下で選択・時点移動、上長押しでサブ機能を呼び、下長押しで時系列操作モードをキャンセルする。サブ機能のない YouTube・風刺画では上長押しは無反応とする。４ボタン側の電源ボタンで待機から復帰する従来合意を維持し、押下時間は未決。

項目一覧型の本体設定メニューや将来のプラグインメニュー内では、サブ機能入力を決定、電源・キャンセル入力をキャンセルとして統一する。４ボタンの PicoMado では左上 GP12 が決定、左下 GP14 がキャンセル。２ボタンでは短押し上下で項目を選び、上長押しで決定、下長押しでキャンセルする。右上 GP13 と右下 GP15 は上／下の選択、または選択中プラグイン内の操作に使える。項目一覧型メニューにこの共通役割を適用する。天気・雨雲の時系列操作モードでは、上記の時点移動とデフォルト表示へのキャンセルを適用する。項目一覧型メニューでの決定後の画面遷移と、将来のプラグインメニューでキャンセルした際の変更保存／破棄は未決（U-05）。接続設定でのキャンセルは上記のとおり変更を破棄する。

初版の通常接続中は、本体設定メニューを開く入口を設けず、プラグイン選択の末尾にも置かない。各プラグインのサブ機能に本体設定を追加しない。接続失敗中・接続作業中の設定入口は上記の決定どおり維持する。将来必要になった場合の拡張は初版の必須要件としない。

単押しにはチャタリング対策を行う。２ボタン長押しの初期値は 1.8 秒とし、端末別 Web 設定で変更・保存する。押下中の判定は切り替えず、次の入力から新設定を適用する。チャタリング時間は未決（U-05）。４ボタンの電源押下時間は別途決める。

短押し上／下は選択、上長押しは通常時のサブ機能呼出しと項目一覧メニュー内の決定、下長押しは電源・操作モード／メニュー内のキャンセルと待機からの復帰に用いる。接続処理中の上長押しは本体設定呼出しを優先する。メニューを開いた長押しが決定として連続発火しないようにする入力判定と、長押し時に短押しを誤発火させない判定は設計事項（U-05）。

既存ボタンは内部プルアップを用い、押下時 LOW。 BLK はハードウェア PWM 対応の GP22（物理29番）へ割り当てる。結線後にソフトウェア側も対応する。待機時は LCD を黒表示にして BLK を OFF にする。ただし現状 BLK は未結線で、黒表示はできてもバックライトの物理的な消灯はできない。比較回路では LOW 消灯／HIGH 点灯だが、実物の回路・極性は未確定（U-07）。極性の設定化と復帰時の元の明るさ保持は設計時の選択肢とする。

元プロジェクトは `/home/tane/dev/PicoW/PicoW_Youtube_Player`。会話上の既存構成では Pi5 が `192.168.0.120`、Pico が `192.168.0.173`、Web が 16152、配信 TCP が 16151 を使用。新機の初期ポートは 16153。IP・運用パス・既存機との併用方法は未決（U-08）。既存 16151・16152 は変更しない。

既存表示では位置調整値 24、RGB 色補正、ガンマ調整、筐体に合わせた 180 度回転を実機承認済みと聞いている。表示を損なわないための継承候補だが、初期化レジスタを含む実際の仕様は元ソース確認後に判断する。
