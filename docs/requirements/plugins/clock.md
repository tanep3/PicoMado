# 時計プラグイン（2026-10-18追加）

- 上部中央に `yyyy/mm/dd（曜）`、下部左にアナログ時計、右に24時間表記 `HH:MM` を表示する。
- 日本時間（UTC+09:00）を使い、秒と秒針は表示しない。時針は分に応じて進める。
- 表示に入った直後、再接続直後、各分の境界で現在時刻を描画する。過去の未表示分を順番に再生しない。
- LCD は既存の160×80 RGB565BE、E-ink は250×122のネイティブ白黒mono1とする。
- 共通のプラグイン順序と端末別ON/OFFを使う。既存4種の保存済み順序はそのまま保ち、時計だけを末尾へ追加する。既存端末の選択・有効化は変更しない。既存端末の時計はユーザーがONにする。新規登録端末は他の対応プラグインと同様に有効となる。
- 時計にはサブ機能や外部取得ジョブを設けない。時刻・画像の定期DB保存、外部時刻API、Pico RTC同期は不要。
- 時計以外を表示中、メニュー／待機中、ローカル画面所有中、オフラインの端末には時計由来の描画・取得・DB書込みを発生させない。
- 送信・描画中の画像を毎分のタイマで失効させない。完了後は最新の分だけを送る。重複通知は同じ表示世代・同じ分の画像を再送しない。

## E-inkの全面更新間隔

- 時刻は毎分更新する。時計の連続表示中の白黒反転する全面更新は既定10分間隔とし、その間はV4部分更新を使う。
- `/plugins/clock` で端末別に1〜60分を指定し、既存の改訂・incarnation検証付きプラグイン設定APIでSQLiteへ保存する。LCDには適用しない。
- 間隔は直前の全面更新を行った時計画像の分から数える。初回・表示切替・再接続・待機復帰・設定変更後の最初の時計画像、時刻が過去へ戻った場合、パネルエラー後は全面更新で基準画像を作り直す。
- 新E-inkファームが `eink-clock-v1` を申告した場合だけ、FrameStartに `eink_refresh:{full_refresh_minutes,minute}` を付ける。`minute` はUnix秒の60による整数商で、物理更新の所要時間により10分が11分へずれない。
- 時計以外の風刺画・天気・雨雲・YouTube・共通ロゴ・ローカル状態画面は従来の全面更新とsleepを維持する。
- 旧ファームでも時計画像は表示できるが、間隔は効かず毎分全面更新になる。Web UIは能力申告に応じてこの事実を表示する。
- 部分更新のSPI手順は公式V4ドライバと既存V4横表示コードを根拠とし、V3のLUTや壊れたfast経路を転用しない。BUSY期限と描画完了ACKを維持する。

## 検証

年月日・全曜日・JST日跨ぎ・年跨ぎ・閏日・24時間表記、時針の分位置、秒による画像不変、両解像度、文字境界、分境界・重複・遅延・再接続、非表示／他プラグインの無更新、移行時設定保持、端末別設定の競合／永続化／削除後リセットを自動検証する。V4基準RAM・部分／全面波形指定・10分境界・sleep復帰・タイムアウト・他プラグイン分離はホストのSPI／メインループ試験で検証する。実機の残像、ちらつき、BUSY時間、電力は実機受入で確認する。
