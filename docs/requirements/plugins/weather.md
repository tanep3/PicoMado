# 天気予報プラグイン要件

[要件定義書の案内](../README.md)と[共通カーネル要件](../kernel.md)を参照する。共通の事前更新・鮮度・失敗表示・閲覧中セット保持は[プラグイン共通運用要件](../README.md#プラグイン共通運用要件)に置く。

## 内容・端末別地域・データ

独立プラグイン。端末ごとの初期地点は東京都の東京駅で、Web UI から各端末の地域を変更可能。今日を含む７日分を日別に表示する。気象庁の地域予報を採用する。東京駅向け７日分のプログラム生成プレビューを表示方式として採用し、他地域と実機表示は要検証（U-10）。

天気の地域はプラグイン固有の端末別設定とし、各端末の初期地点を東京都の東京駅にする。Web UI の天気プラグイン設定では気象庁の対応地域・気温代表地点の一覧から端末ごとに選び、ほかの端末の地域は変えない。初版では住所の自由入力や GPS からの自動変換を設けない。変更した地域は端末固有設定として保存し、サービス再起動後も保持する。画面内の具体的な項目・対象端末の指定方法は設計事項（U-04、U-14）。

天気の情報源は気象庁の公開データとし、その提供範囲内で表示する。天気の Web 設定地点は、対応する**予報区域**と**気温の代表地点**に結び付ける。東京駅を含む任意の設定地点について、その地点そのもののピンポイント予報と誤認させず、画面で予報区域と気温地点を区別して示す。提供されない気温は `ーー` と表示し、0 と扱わず、実測値と予測値を混ぜて補わない。湿度は取得できる場合のみ表示し、この確認済み予報 JSON にない値を無理に補完しない。

**調査済みの公開例・製品未実装。** [東京都の気象庁予報 JSON](https://www.jma.go.jp/bosai/forecast/data/forecast/130000.json) では、確認時点で週間予報は明日から７日分で、初日の気温欄に空値があった。今日を含む７日分には短期予報と週間予報を対象日付で結合する案を設計候補とする。区域・代表地点への対応、欠損を含む日付結合、全設定地域での取得・表示は未検証（U-10）。

[天気描画実験](../../../experiments/jma-weather-render/README.md)では、東京駅向けの７日分をプログラムで PNG に描き、LCD 160×80 と E-ink １bit 250×122 のプレビュー表示方式を確認した。この画面の配置・表現を採用する。天気の画像生成に LLM は使用しておらず、実機画面の表示結果ではない。天気の他地域や端末での見え方は未検証（U-10）。

## 日別操作

デフォルト表示は今日。今日を含む７日分を保持し、表示対象日を分かるようにする。下ボタンは翌日、上ボタンは前日方向へ移動し、今日より前と７日目より後には進まず、その場で停止する。末尾から今日へ循環しない。各日には天気マークと最低・最高気温を表示し、湿度も取得可能なら表示する。欠損する最低・最高気温は `ーー` とし、0 や異なる種別の気温で補わない。表示する予報区域と気温代表地点を区別する。情報源は気象庁に決定した。今日を含む７日分を短期・週間予報から対象日付で構成できるか、予報区域と代表地点の対応を含めて検証する（U-10）。

## 取得の初期設定

外部 HTTP 取得は１回 20 秒でタイムアウトし、初回後に２回再試行する。タイムアウトと追加再試行回数は、このプラグインの Web 共通設定で変更・永続化できる。変更は次に開始する取得ジョブから使い、進行中の結果と新設定の取得セットを混同しない。再試行間隔は実測後に決める。
