# YouTube プラグイン要件

[要件定義書の案内](../README.md)と[共通カーネル要件](../kernel.md)を参照する。入力・配信・端末選択の共通規則はカーネル正本に置く。

## 対象と再作成方針

既存の機能・例外・運用上の工夫を抽出し、Rust プラグインとして再作成する。既存設定の実態確認は U-09。

既存ソースの一部は 2026-10-12 にローカルで読み取り、[機能抽出・互換チェック](../../legacy-compatibility-checklist.md)に記録した。実機動作・Rust 再作成時の成立と網羅的な差分は未検証であり、U-01・U-09 で照合する。Python の構造をそのまま移植しない。既存本番は変更しない。

## 視聴端末間の共有

初期 YouTube プラグインは、視聴端末間で動画と再生位置を共有する。各端末のプラグイン選択と待機・接続状態は独立する。端末 A が天気へ切り替えても視聴中の端末 B は止まらず、A が YouTube に再参加すると共有中の現在位置から表示する。動画の変更は、その時点で YouTube を視聴している全端末へ反映する。フレーム単位の厳密な同期は要求せず、遅い端末がほかの端末の配信を止めない。共有コンテンツ・再生状態と端末固有の状態を区別し、YouTube プラグインが共有範囲・再生状態・送信先を管理する。視聴端末数に応じる PUSH 接続数・帯域、共有位置の更新基準、遅い端末の送信処理、表示能力が異なる端末間での扱いは設計・測定事項（U-14、U-15）。

2026-10-15 の指示により、FPS は各取得・変換フォームで **6・12・18・24・30 fps から必ず選択**する。独立した既定 FPS 設定欄は置かない。最後の選択をブラウザに保持し、未保存の場合のフォーム初期選択は 12 fps とする。要求には選択値を必ず含め、未指定・null・非対応値は変換開始前に拒否する。過去の保存設定は互換読取りを維持し、既存の変換済み FPS を変更しない。自動更新で編集中の選択を巻き戻さない。30 fps の実機達成は未検証。

## 原本取得・範囲・キャッシュ

新たな取得では低解像度の原本全体を保存し、ローカル ffmpeg で指定区間・FPS・160×80へ変換する。終了は元動画上の絶対位置で、空欄は最後まで。開始36秒／終了空欄と、12～184秒を受け付ける。変換の条件キーには動画・区間・FPS・変換版を含め、同じ FPS でも異なる区間を混同しない。既存の完成変換と、範囲を満たす既存原本・旧部分素材を再利用する。

原本の新規取得は初期上限512 MiB、取得・変換中は空き1 GiBを確保する監視を置く。既存素材の自動削除は行わない。詳細と運用上書きは[実装・検証記録](../../../service/youtube-media-verification-2026-10-15.md)を参照する。成功・失敗・取消し時の作業領域の片付けと、失敗時の既存再生維持を継続する。診断には位置・長さ・FPS・容量等の数値を残し、署名URLや認証情報、ツール生出力を永続ログへ出さない。

## 個別削除と Web 表示

原本と単一変換版を別々に削除できる。原本削除は変換済みと再生を保持し、変換版削除は原本・他FPS・同FPSの別区間を保持する。確認にはタイトルと対象のFPS・区間・形式を示し、IDの手入力を要求しない。取消しは削除要求を送らず、二重送信を防ぐ。対象の変換中は取消完了を待ち、再生中の変換版だけ停止してから削除する。

PCでは **FPS／秒／解像度／容量／ID／再生／削除** の順に1行表示する。スマホでは情報を折り返し、再生・削除を隣り合う押しやすいグループに保ち、横はみ出しを生じさせない。ダーク表示を維持する。処理状況は進行中・取消中・失敗を表示し、完了済みや空の処理枠は出さない。

## 既存機の参考情報（ソース照合・実機未確認）

既存の動画方式は、Pi5 が yt-dlp/ffmpeg で取得・変換・キャッシュし、RGB565 フレームを TCP で Pico に配信するもの。Web で URL、切り出し範囲（既定は全体）、履歴・タイトル・作者・サムネイル・容量表示・手動削除を扱い、6/12/18/24/30 fps を選択でき、現行 Web の既定は 6 fps とソースで確認した。既存の機能・例外・運用上の工夫を Rust で継承する方針だが、項目の実態と設定値は元ソース確認が必要で、新環境で 30 fps の達成を保証するものではない。Wi-Fi 性能の変動と、長大キャッシュの走査／共有ロック問題も既存機で経験している。
