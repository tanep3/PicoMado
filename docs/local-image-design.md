# ローカル画像プラグイン設計（LOCAL-IMAGE-20261105）

既存 `ContentPlugin`、ジョブ実行、静止画配信、E-ink の native フレームを利用する。`local-image` は LCD/E-ink 両方を支持し、準備完了した RGB565 と mono1 のペアを選択状態として保持する。起動後は保存済み変換物を検証して復元する。アップロード入口は `local-video` と同じストリーム・一時ファイル・同名拒否方式を再利用する。

変換ジョブは入力を安全に開き、center crop で LCD と E-ink の各寸法へ整形する。LCD は RGB565、E-ink は一時 PNG を外部 CLI に渡し出力を検査して mono1 にする。完成した LCD/E-ink バイト列はプラグイン状態に保存し、再起動後に復元する。外部 CLI は配布物に付属する実行ファイルのパスを優先し、開発用に明示的な絶対パスを指定可能にする。PATH 上の不明な同名コマンドへ黙ってフォールバックしない。

配布は上流 `pic2gray4px` の新 Release をトリガーとして PicoMado の各対象 OS/CPU 向けバンドルを自動生成する方式を第一候補とする。上流が配布したアセットとチェックサムを検証し、バンドル manifest に上流版・SHA256・対象アーキテクチャを記録する。これなら PicoMado ソースの版指定を手動で更新せず、利用者は一つの PicoMado 配布物を得られ、実行時ネットワークを必要としない。上流 Release の不変性または署名、下流ワークフローの権限、失敗時に旧バンドルを保持する条件が必要である。代替のインストール時・利用時「最新」取得は即時反映できるが、再現性、オフライン利用、公開元の乗っ取り時の影響、更新失敗時の継続動作に弱い。現在は上流に Release がなく PicoMado に正式配布工程もないため、どちらも未実装・未検証である。既存の手元の実行ファイルと明示パスによる開発検証のみ可能。

受入試験は縦長・横長・透過画像の切り抜き、LCD 色、E-ink 出力寸法、CLI 不在・失敗、上限・危険なファイル名、削除境界、再起動復元、既存プラグイン順序移行を含む。USB/実機描画やサービス更新はこの変更では行わない。
