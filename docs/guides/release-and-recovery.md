# 安定版を決める前に・戻すときに

この文書は配布前の確認項目です。現時点で一般公開済みの安定版や万能な復旧用ファームがあるという意味ではありません。操作は所有者の承認と実機ごとの確認が必要です。

## 安定版の条件

1. 対象のソースコミット、変更 ID、root gate の check receipt、独立レビュー、サーバ実行ファイルと UF2 の SHA256、SDK・ビルド receipt を一組として記録します。テストが通っただけでは運用適用・効果確認まで完了しません。
2. [対応表](hardware-support.md)にある機種ごとにビルドと検証状態を区別します。未検証の Pico 2 W、ESP32、画面・部品を対応版へ含めません。公開タグ・配布物・説明文は同じコミットに対応させます。
3. 設定例に秘密値、個人の絶対パス、実機 ID、生成素材が含まれないことを確認します。第三者フォントの [権利表示](../../service/assets/NOTO-COPYRIGHT)も同梱します。

## 更新前の退避

現在動いている実行ファイル、設定、DB、各 plugin の `data/`、必要な `cache/`、機種とボード ID に結び付いた旧 UF2・manifest を対応付けて退避します。SQLite の WAL が動いている間に DB 本体だけをコピーしません。整合した退避には、承認済みの停止または SQLite の安全なバックアップ手順を使います。新しい設定例を既存のファイルへ上書きせず、データを自動移動しません。

## 問題が出たとき

新しいバイナリや UF2 を繰り返し試す前に、症状、時刻、対象端末、コミット、receipt、設定の版を記録します。旧バイナリだけを戻しても新しい DB schema と合わない場合があるため、整合する旧設定・DB・素材の組合せを確認します。ファームを戻す場合は対象の Flash ID と旧 UF2 の結び付きを offline preflight で確認し、所有者が端末を識別してから書込みを検討します。復旧後は起動、接続、表示、入力を別々に確認します。

`python3 tools/project_gate.py check` は開発ゲートであり、サービス操作や実機書込みの許可ではありません。直接ビルド・flash・deploy でゲートを迂回しないでください。
