# PicoMado を初めて設定する

この手順は Linux と Pico W を想定します。まだ実機で確認されていない構成は[サポート表](hardware-support.md)を確認してください。既存の PicoMado を使っている場合、設定、DB、素材は自動移動も上書きもしません。

## 1. 自分の環境を確認する

端末で `echo "$HOME"` を実行し、自分のホームを確認します。`/home/tane` をそのまま自分の設定へコピーしないでください。Pico SDK の場所を確認し、ビルド時は `PICO_SDK_PATH` にその場所を指定します。風刺画プラグインで Python の個人用仮想環境を使う場合は、各自のホーム以下に作ります。既存の `~/dev/PicoW/PicoW_E-ink_Display/.venv/bin/python` があれば利用し、別の場所ならサービス環境変数 `PICOMADO_CARICATURE_PYTHON` にその実行ファイルの絶対パスを指定します。見つからない場合は `python3` を使うので、必要な Python パッケージを使う人自身の環境へ用意します。

## 2. サーバの設定を作る

`service/deploy/config.toml` を自分の `~/.config/PicoMado/config.toml` にコピーします。`bind` の例示 IP を、自分のコンピュータが使う LAN アドレスに変更します。全アドレスを受け付ける `0.0.0.0` は拒否されます。DB と plugin の保存場所は `~/` から始まるので実行ユーザーの HOME に展開されます。別の場所を使う場合は両方を対応する絶対パスにし、DB を plugin root の `data/` 直下に置きます。設定を保存する前に既存 DB を上書きしないでください。

実行ファイルは既定でこの設定を読みます。別の設定を試す場合は `picomado-server --config /絶対パス/config.toml` と指定できます。設定の読み込みに失敗したら、先に TOML の書式と IP/パスを直してください。

## 3. ファームの個体設定を用意する

`firmware/devices/sample-a/config.sample.h` はダミーの Wi-Fi 値を持つ例です。自分の端末名のディレクトリに `config.h` と `board-id.txt` を作り、秘密値を Git に追加しないでください。同じディレクトリの `profile.txt` で検証済みプロファイルを一つ選びます。新しく作る `config.h` に対応する `#include "プロファイル名.h"` を置き、旧 config の重複する画面・ボタン定義は取り除きます。画面の BLK 接続有無や E-ink のパネル接続有無は個体ごとに設定します。既存の秘密 `config.h` は、定義が選択プロファイルと一致すれば旧形式のまま使えます。自動書換えはしません。

`firmware/README.md` に各端子と接続手順があります。ボード ID の確認や書込みは実機を持つ人が別途行う操作です。サンプルビルドは実機用ではありません。

## 4. 確認と復旧

開発者向けのオフライン確認は `python3 tools/project_gate.py check` です。既存端末の設定や DB を残したまま新バージョンを検討し、変更前の実行ファイル、設定、DB、plugin の `data/` を整合する時点でバックアップします。戻すときは保存した同じ組合せを復元し、端末ファームも対象個体に一致するものを使います。サービス停止や実機書込みはこの文書だけで許可されません。
