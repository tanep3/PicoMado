# LCD fixed-operation implementation handoff

Implementation is restricted to LCD-FIXED-UPDATE-20261027, source 17e231ffa9db9b9cc9d93ecd55444eae0b7f26b1, example-lcd and its fixed UF2 hash. Normal preflight remains on its existing ship path. PM_FIXED_OPERATION and PM_FIXED_OPERATION_REVIEW select the reviewed operation through the existing flash script, retaining manifest, hardware profile and unique BOOTSEL board checks.

The historical source subject is reconstructed from tracked files in a temporary source snapshot. Existing check-proof and build-lineage verification still validate historical logs, actual SDK/toolchain/build flags and current private device configuration. Current implementation must be committed and clean. Its exact HEAD and operation hash must be accepted by both an independent reviewer and parent. No approvals are issued by this implementation.

Approval procedure: obtain the operation JSON prepared in /tmp/picomado-lcd-fixed-operation.json. Review the exact implementation HEAD and this JSON. The independent review JSON must have operation=LCD-FIXED-UPDATE-20261027, accepted=true, reviewer different from operation implementer, implementation_commit=the exact HEAD and operation_SHA256=SHA256 of the operation JSON. Parent approval JSON must have the same operation, implementation_commit and operation_SHA256 plus owner=parent, accepted=true and independent_review={path: absolute review path, SHA256: review file hash}. Store these outside tracked inputs. Review expires with the operation; changing any bound data requires renewed approval. No pending review is acceptance.

Then run the existing flash entry first with --verify-only and the two PM_FIXED_OPERATION variables. Physical flash remains separately authorized and requires reconfirming one matching USB board. No physical operation was performed during implementation.

Validation: operation admission unit fixtures cover valid admission, wrong artifact/device/board/config/profile, changed receipt/candidate, missing parent/independent/firmware acceptance, stale implementation/approval hash, self review, expiry and revocation. Existing gate/build/ship tests cover ordinary paths. Fixture positive metadata is not a production approval. Actual historical subject/check and build-lineage verification also passed against the preserved real LCD candidate.
