### Target scope versus neighbor freshness re-evaluation

The original USB observer requirement lists a known-MAC `REACHABLE` neighbor, route, selected PID-owned control socket and unique ESTABLISHED TCP socket, inode/cookie, and before/after host session. The implementation checks `REACHABLE` before collecting the rest. The purpose is to restrict a header-only observer to the intended LCD's exact interface and TCP four-tuple; the BPF independently restricts packet headers to that tuple, and the observer rechecks ownership/cookie before START and during capture. `REACHABLE` contributes a recent kernel reachability indication for the cached MAC→IP entry, but it neither maps a host application connection ID to an inode nor proves future wireless delivery. The [Linux ip-neighbour manual](https://man7.org/linux/man-pages/man8/ip-neighbour.8.html) calls `STALE` valid but suspicious and `DELAY` delayed validation; neither alone means the MAC/IP identity changed. Thus requiring fresh reachability at each stage is stronger than this observer's *target scope* purpose and changes with time during the five-second USB preparation.

For the LCD diagnostic path, a single pure admission decision may accept only a unique known MAC on the requested interface with the expected peer IP and state `REACHABLE`, `STALE`, or `DELAY`, **plus** the exact local route, one selected-PID-owned ESTABLISHED peer socket, nonzero inode/cookie, matching host target/boot/connection/session, and the same tuple/PID/incarnation/inode/cookie and binding before and after ARM. Its result must say `scope_bound=true` and report the original NUD state; only `REACHABLE` may report `recent_kernel_reachability=true`. Missing, duplicate, changed MAC/IP/interface/route, `NONE`/`INCOMPLETE`/`PROBE`/`FAILED`, ambiguous or changed socket/cookie, process or session must fail. Adapter reads supply facts; a pure rule composes them. This is sufficient for the current exact header-capture scope under the configured known-MAC trust boundary; it is not authentication of a physical board, fresh peer reachability, RF departure or a measurement-success decision. A physical replacement that impersonates the same MAC/IP and existing TCP connection would be outside both this rule and the old `REACHABLE` rule's guarantee.

This re-evaluation supersedes the earlier proposal to move a NUD wait after ARM. The implemented `target_scope_decision` has no IO and returns scope and recent reachability as separate facts. The existing resolver still obtains one PID-owned ESTABLISHED socket, verifies its control socket and inet_diag cookie twice, and the observer itself checks socket ownership/cookie before START and during capture. The LCD heartbeat runner alone opts into the cached-mapping scope rule before and after ARM, passing the first resolved target to the same pure decision for exact pre/post comparison; the general USB button trial keeps its prior `REACHABLE` requirement. The accepted mapping must be unique for both known MAC and peer IP, with a direct matching route; `STALE`/`DELAY` never become a claim of current reachability. Source commits: design `71b30f8`, implementation `2f58fdd`.
