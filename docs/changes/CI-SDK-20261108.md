# CI-SDK-20261108: CI の Pico SDK 依存を明示する

## 原因と比較

2026-11-08 の GitHub Actions `tests` run [42474916744](https://github.com/tanep3/PicoMado/actions/runs/42474916744) は `firmware/tests/run_home_static_arp_tests.py` が lwIP の `etharp.c` を読めず停止した。実機障害を示す結果ではない。標準 host テストはローカルでは隣接する Pico SDK を参照できるが、CI は PicoMado だけを checkout しており SDK と submodule を取得していなかった。SDK 依存の host テストを追加した際、CI の環境構築を対応させなかったことが混入原因、隣接 SDK が存在するローカル環境だけで確認したことが見逃し原因である。

## 修正前の契約

- 変更対象は CI の依存取得・事前検証と、その回帰試験・記録のみ。firmware/service の製品コード、共有 SDK、実機と稼働サービスは変更しない。
- `push` と `pull_request` の既存自動実行を維持する。最終方針は CI を有効なまま使うことであり、成功後の再停止は行わない。
- CI は公式 `raspberrypi/pico-sdk` の Pico SDK 2.3.1、commit `079c6f39023649b154152db30f1d781e884879bc` を独立した CI 用ディレクトリへ取得し、submodule を再帰取得する。この SHA は今回のローカル試験に使う未変更 SDK と同じ。
- `PICO_SDK_PATH` を明示し、host テスト前に SDK の commit、submodule の初期化・一致、および実際に使う lwIP / CYW43 / flash-helper ファイルの存在を読み取りだけで検証する。不足時は具体的な環境エラーで停止する。試験スキップや失敗の成功扱いをしない。
- 回帰試験は完全な依存、SDK 不在、必要ファイル欠落、異なる revision、未初期化・異なる submodule を区別する。
- 既存 Python / firmware host / firmware USB / server の全 CI 試験をローカルで実行する。ローカル ARM64 の結果と GitHub Ubuntu runner の結果を分け、GitHub 実行前に全体成功としない。

## 適用境界

正本 `main` に変更をコミットする。push はユーザーが行う。現在の GitHub workflow は手動無効化されているため、再有効化と新コミットの GitHub 実行は別の未適用段階として追跡する。古い失敗 run の再実行は古い workflow のため今回の修正を反映しない。失敗履歴は削除しない。
