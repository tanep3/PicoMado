## 問題と比較軸

README が工作プロジェクトの入口として情報不足で、初回設定ガイドが個人のホームパスを再掲していた。公開文書には個人のローカルパスとネットワーク値が複数残り、古い実装状態を現在形で述べる箇所もある。既存の設定例・ハード対応表・実装に対し、利用者が初回設定をたどれるか、歴史的記録を現在の手順と誤認しないかを比較する。

## 修正範囲と状態

利用者向け `service/README.md` と `firmware/README.md` は現在の導入入口と実装の概説に絞る。日付付きの旧手順と観測は各ディレクトリの `history/` へ移し、相対リンクの参照先を保つ。削除や現在の適用結果への読み替えはしない。

文書ファイルの一覧は内部監査用の収録目録であり、リンク先を全て含む独立配布物ではない。ユーザーの作品確認には、同じ README 本文と実機画像を埋め込んだ自己完結 HTML を用いる。HTML 内で収録しない文書への相対リンクは無効な案内にしない。ソース配布の可搬性と私的証拠の公開可否は別課題として残す。

## 公開境界の設計

利用者向け README、初回設定、対応表、設定例では個人の実値を使わず、説明用アドレスを明示する。時刻付き Markdown の置換値は実測事実として読めないよう、各文書に匿名化注記を置く。構造化チェックポイントは証拠の参照関係を変えずに保持し、一般公開対象から分離する。ローカル実験専用コードの固定パスと IP は環境から指定するか説明用の値へ変え、通常サーバ・端末の実行契約は変更しない。履歴改変、証拠削除、実機操作は行わない。
