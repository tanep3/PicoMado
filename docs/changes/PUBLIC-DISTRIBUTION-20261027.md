# PUBLIC-DISTRIBUTION-20261027 — 公開配布と利用者経路

## 課題と比較軸

既存の内部開発ゲートは変更証拠と独立承認を要求する。一方、初回利用者は内部記録を持たない。公開利用者のビルド・書込みではハードウェア構成、対象、成果物の同一性を引き続き検証し、内部承認の存在に依存しない経路が必要である。既存の開発ゲートを無効化しない。

個人 profile は未追跡でも利用でき、個人設定は公開候補に含めない。初回依存取得とオフラインビルドを分けて説明する。公開候補は履歴を含まず、内部記録と個人情報を分離し、必要なソース・素材・ライセンスを含めて検証する。既存 main 履歴の情報は残るため、その履歴を公開候補に含めない。

プラグイン例は UI 設定から端末表示までの経路と、検査の入力・出力の位置を一致させる。ソフトウェア試験と実機での確認は区別する。
