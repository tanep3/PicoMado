# PUBLIC-DISTRIBUTION-20261027 — 公開配布と利用者経路

## 課題と比較軸

既存の内部開発ゲートは変更証拠と独立承認を要求する。一方、初回利用者は内部記録を持たない。公開利用者のビルド・書込みではハードウェア構成、対象、成果物の同一性を引き続き検証し、内部承認の存在に依存しない経路が必要である。既存の開発ゲートを無効化しない。

個人 profile は未追跡でも利用でき、個人設定は公開候補に含めない。初回依存取得とオフラインビルドを分けて説明する。公開候補は履歴を含まず、内部記録と個人情報を分離し、必要なソース・素材・ライセンスを含めて検証する。既存 main 履歴の情報は残るため、その履歴を公開候補に含めない。

プラグイン例は UI 設定から端末表示までの経路と、検査の入力・出力の位置を一致させる。ソフトウェア試験と実機での確認は区別する。

## 公開利用者の契約（実装前）

- 開発者向け root gate の admission、証拠、承認と、その拒否条件は変更しない。配布版には利用者が自分の環境で実行する別経路を設ける。利用者の確認は独立レビューの証拠と称しない。
- 配布物は Git 履歴に依存しない。ソースと必要な資材、検査・ビルド・preflight の実行物、ライセンスを含む。公開対象は明示的に選び、内部変更・観測証拠、個体設定、ボード ID、Git メタデータを含めない。公開可能な記述も中身を検証する。パターン検査だけで秘密がないと保証しない。原本と履歴は私的に保存し、既存 main の履歴を変更しない。
- 検査は対象ソースをハッシュに結び付け、変更された入力、欠落した検査結果、失敗した検査を拒否する。生成物とローカル個体設定は検査ソースの列挙から明示的に分ける。利用者がソースや配線プロファイルを変更した場合は再検査する。
- ビルドはロック済み依存を使い、実行したソース、ツール、SDK、プロファイル、個体設定、ボード ID と成果物を記録する。ファームでは既存の MCU・ドライバ・GPIO・config 検査を通す。preflight は対象、設定、プロファイルと成果物の変更を拒否し、対象が１台で Flash ID が一致した後にだけ書込みを行う。ソフトウェア検査は物理配線や表示の成功を保証しない。
- 保存する証拠には個人設定や識別子の実値を公開しない。ローカルに作る receipt の保存場所と権限も説明する。仮の承認や成功を生成しない。実機の確認は別の未完了段階として記録する。
- 公開候補の新しい環境で依存取得、設定生成、サーバ・ファームの検査とビルド、プラグイン例を順に試す。ブラウザの保存・再読込・競合と配信は隔離サーバーで確認し、実機やクリーン OS を使わない結果はその制限を明記する。

## 方針変更：通常のビルドと UF2 書込み

利用者と作者の通常作業に、独自の check・receipt・承認・manifest や個体 Flash ID 照合を必須にしない。ファーム起動時も特定の実機 ID を要求しない。通常の Pico W と画面プロファイルの選択、実装済みドライバ・GPIO の矛盾検出、機能に必要な設定の整合は維持する。開発テストは任意で実行できる。個人設定と内部記録・Git 履歴を公開物から分離する方針は変更しない。
