# Restore LCD AWAY Endpoint Exchange

The accepted LCD EEX1 implementation resolves the phone SOCKS5 endpoint after AWAY obtains an IPv4 address, verifies it through SOCKS authentication and CONNECT, and reuses that verified endpoint only within the same Wi-Fi connection generation. A new Wi-Fi generation or relevant IP/gateway/netmask change invalidates it. HOME remains direct TCP. EEX1 is a required product AWAY path: a real LCD build defaults to ON and rejects an explicit OFF. Sample and unbound diagnostic builds may retain an OFF fixture; they are not flashable product images.

The verified EEX1 image `7cdc47bf...5cdf80` discovered `10.244.95.133:48115` on real hardware. The previous LCD recovery image `9d4f66d1...b36479687` also included EEX1. The later installed frame diagnostic image `efa09ede...06e8233a` and current PR155 image `77c40a06...dc90e9` were built with EEX1 OFF. On 2026-10-22 the phone advertised `10.244.95.133:48115`, while the LCD's static fallback was `10.101.65.232:48115`; the LCD obtained an IP but repeatedly failed in the TCP stage before SOCKS negotiation. Updating the fallback IP alone would fail on another hotspot address change.

Restore the current PR155 firmware source and private SDK overlay with the same LCD board ID, ignored device config, SDK pin, ACK-path/USB/TX/CY/EV1/stream flags, PM NONE behavior and TCP_NODELAY. Require EEX1 in product LCD builds and retain UDP discovery port `48116`. Do not change credentials, Pi target, server, settings sector, LCD draw or button contracts. Use an isolated build directory and retain the current and prior recovery UF2s. Verify effective CMakeCache and compile commands, reject the product OFF configuration, check UF2 address bounds, map/stack/RAM against the accepted EEX1 build, run the existing EEX1 host suite and the PR155 exact-SDK test. The EEX1-enabled build may change many linked bytes; compare source and effective flags, not a two-block UF2 expectation.

The candidate is ready for physical application only after target Flash ID `E661640843239D21`, exact UF2 SHA, source/config/SDK, settings nonoverlap and independent review are checked. After one LCD-only verify/write/reboot, observe fresh EEX1 discovery, SOCKS METHOD/AUTH/CONNECT, Pi Hello and frame receipt/render report separately. Compare HOME direct connection and the existing finite LCD switch sequence with the current ACK-independent server. A successful EEX1 endpoint report alone does not prove Pi or display success. Preserve the user's current selection. Device operation and effect remain unverified until the real test.
