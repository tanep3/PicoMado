# BT-AUDIO-20261107 — PicoMado Bluetooth audio / remote input

## 目的と境界

PicoMado の Pico W から Bluetooth Classic スピーカーへ A2DP 音声を送り、AVRCP の操作を端末入力として使えるようにする。マイク/HFP/SCO は本変更の対象外で、別の PicoW_Bluetooth_lib 調査を待たない。PicoMado を母艦 Bluetooth のリモコンに置き換えるものではない。

ユーザーの仮説は「ライブラリ完成を待たなくても、A2DP と AVRCP を PicoMado に実装できる」。BTstack を直接利用する独立 adapter とし、未完成ライブラリをコピー・内包しない。別リポジトリの実証は比較材料として使う。配布用依存を新たに導入する場合は別途明記する。

## 現状の根拠

- 調査開始時 PicoMado 正本 main: `b5a2c16`、作業ツリー clean。
- 既存 Want: `docs/requirements/README.md` の Bluetooth 音楽再生。Web UI から接続先指定、Pico が音声を送る方向。
- PicoW_Bluetooth_lib の `docs/evidence/2026-11-07-a2dp-player-hardware.md` に、LBSで48kHz・440Hz・3秒の再生と明示再接続の実聴取あり。同文書で AVRCP、長時間、Wi-Fi共有runtimeは未検証。
- PicoMado は `pico_cyw43_arch_lwip_threadsafe_background` を使用。別ライブラリの単独runtimeをそのまま起動して二重所有させない。
- 端末の既存入力は `pm_operation` と `perform_operation` に集約され、0ボタンのE-inkでも論理入力経路を持つ。

## 採用する責務分割（設計案）

1. **Bluetooth adapter**: Pico SDK/BTstackを所有する薄いC adapter。初期化・GAP・SDP・A2DP Source・AVRCP Target・SBCエンコードを担当。CYW43は既存初期化を共有し、二重init/deinitしない。callbackから表示/ネット送信/ファイルIOを実行しない。
2. **AudioSession aggregate**: 有界の接続/再生状態、世代、エラー、PCMキューを所有。Query→純粋な遷移→adapter effectとする。接続失敗や未接続が表示や物理入力の進行を止めない。
3. **Server audio executor**: 音源の取得/デコードは母艦側。音源プラグインは再生意図を提供し、共通層へプラグインID分岐を増やさない。既存動画から音声を得る実装は共通音声配送が成立してから行う。
4. **Remote input adapter**: AVRCP pass-throughを有界イベントへ変換。既存の端末入力APIを呼ぶ。GPIO数によって無効化しない。AVRCPが接続したこととボタンが届いたことは別の検証項目。

## Web UI と端末別接続の必須契約

ユーザー追加要件：複数のPicoMadoが各々別のBluetooth機器へ接続する。Web UIホームの各端末設定から探索→候補選択→ペアリング、ON/OFFを操作できるようにする。

- 入口は既存 `service/src/ui.html` のホーム端末カード内。共通設定や音源プラグインのページへ混ぜない。
- 探索は母艦ではなく選択したPicoが実行する。候補にはその探索世代の名前・アドレス・対応情報を表示し、別端末/古い探索結果を混ぜない。
- 端末別のdesired state（有効/接続先）とobserved state（探索中/ペアリング中/接続済み/失敗）を分離。ボタンを押しただけで「接続済み」にしない。
- ONは保存済み接続先への接続を開始できるが、未選択の機器へ勝手にpairしない。OFFは探索・接続・音声を停止、接続情報の削除と区別する。
- ペアリング鍵をUI/API/logに出さない。保存する場合は端末側の既存flash領域との競合・原子性・消去範囲を設計する。Wi-Fi資格情報の領域を上書きしない。
- 設定更新は既存のdevice incarnation/revisionを利用。探索/接続の一過性操作はcommand ID/期限/セッション照合を持ち、再接続時に旧コマンドを再実行しない。
- オフラインではON/OFF等の希望設定保存と、実行できない探索/ペアリングを区別する。Bluetooth非対応ファームには実行ボタンを出さず、必要な更新を案内する。
- 1台が別機器を使っても他端末の候補・接続・再生を変更しない。同一スピーカーの同時利用は保証せず、機器側拒否を正しく表示する。
- UI回帰：探索連打、OFF/キャンセル、途中切断、設定競合、古い応答、機器名のHTML表示、2端末同時操作、0ボタンE-inkを含めて検証する。

## 段階と受入

### A: 音声配送に依存しない端末統合

- 初期値はBluetooth無効。既存LCD/E-inkビルドの通信・表示挙動を維持する。
- 実験ビルドで既存Wi-Fi接続/表示を保ったまま、明示接続した相手へ有限テスト音を再生する。これを音源プラグイン完成と呼ばない。
- AVRCPのpress/releaseを区別し、同一pressの重複を除去。未知/非対応命令は拒否し、誤ってPOWERへ変換しない。
- 操作の候補はNEXT→DOWN、PREVIOUS→UP、PLAY/PAUSE→SUB。POWER、STOP、音量の流用は自動採用しない。最終割当はユーザー確認後に固定する。
- 接続/切断/再接続、途中キャンセル、音声underflow、満杯、古い接続callbackをhost試験。実機ではLCD/E-ink・Wi-Fi共存・AVRCP各ボタンを確認する。

### B: 母艦からの実音声

- 音声のフォーマット/サンプル位置/世代を表示frame tokenと混同しない。
- capabilitiesで交渉した端末だけに配送。旧端末へ新しい音声messageを送らない。
- PCM候補は16bit LE stereo/48kHz（192kB/s）。端末は小さな有界buffer、SBCはPicoで生成し、再生時計はBluetooth送信側に置く。実機負荷に応じ母艦SBC方式との比較を行う余地を残す。
- 音声は画像のlatest置換を使わない。世代と連続sample位置を検証し、欠落は明示的なunderflow/再同期とする。無期限bufferは禁止。
- 初期は独立した音声ストリームの有限試験を先に行い、動画と音声の同期・競合/優先度・一時停止/再開の契約を定めてからYouTube/ローカル動画へ接続する。
- 設定はdevice単位。接続先・接続状態・失敗理由をWeb UIで表示する。他デバイスの音声や表示へ影響させない。

## 検証計画

- Bluetooth OFF時の既存host tests、server tests、ARM LCD/E-ink build。
- adapterをfakeにした接続状態/世代/入力press-release/PCM境界試験。
- Bluetooth ON時のARMサイズ・stack・音声buffer上限を記録。
- 実機A2DP出音とAVRCP操作はユーザー確認。0ボタンE-ink操作、LCD/E-ink表示共存、Wi-Fi再接続、長時間再生はそれぞれ別証拠。
- 実機書込・本番サーバ反映・再起動は別途承認。HFP担当のPico/LBSを同時に開かない。現段階ではUSBを使わない。

## 現在の段階と残る決定

設計草案。仕様コミットを実装前に固定する（`docs/development-process.md`）。独立検証・実機適用・最終クローズは親の担当。AVRCPの操作割当と、最初に配信する音源を確認する必要がある。長時間/AV同期を含めた完成を本草案や単体ビルド成功から宣言しない。
